A consumer gates a downstream claim on an **affirmative success token** issued by a
subordinate authority — an external tool's exit code, a job record's terminal status, a test

wider** than that token's issuing contract guarantees.

Nothing is missing. Nothing is dropped in a last hop. **The token is TRUE.** The *inference*
is what fails. `exit 0` means the process ran to completion, not that its model was valid.
`status=succeeded` means a state machine reached a terminal node, not that the work it names
occurred. `PASS` means an assertion sequence completed, not that it ran against the subject in
the label. A stored verdict was true *when computed*, not that it is true *now*.

Because the token is true, **every test that asserts the token stays green.** That is why this
class survives ordinary review, and it is why you must reason about contracts, not about tests.
